# CI/CD: GitHub Actions (spec)

Kaynak: 2026-10-13 CI/CD brainstorming'i. Repo GitHub'da (`iamhankaya/watchparty`, private). Bugün deploy yalnızca lokal PowerShell script'leriyle (`deploy/`) yapılıyor ve hiçbir kontrol otomatik koşmuyor.

> **Değişiklik (2026-10-13, uygulama sırasında):** Hesap AWS'nin yeni kayıt deneyiminin Free Tier planında; AWS'nin yönettiği, değiştirilemeyen SCP `iam:*Provider*` işlemlerini yasakladığı için OIDC sağlayıcısı kurulamıyor. Kullanıcı kararıyla deploy kimliği, aynı dar politikaya sahip IAM **kullanıcısı** `watchparty-github-deploy` oldu; access key CLI ile üretilip ekrana yazılmadan GitHub secret'larına (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`) aktarılır, Terraform state'ine girmez. Aşağıdaki OIDC/rol/`AWS_DEPLOY_ROLE_ARN`/`github_repo` maddeleri bu değişiklikle geçersizdir; OIDC'ye dönüş `docs/BACKLOG.md`'de.

## Kararlar

| Konu | Karar |
|------|-------|
| Kontroller (CI) | Her push ve PR'da otomatik; AWS'ye erişmez |
| Deploy tetikleyicisi | Yalnızca elle ("Run workflow"), yalnızca `master`'dan; seçenek `frontend` / `backend` / `ikisi` |
| Neden otomatik deploy yok | Backend deploy'u bellekteki lobileri düşürür; izleme sırasında yapılan bir push lobiyi kapatmamalı |
| Deploy ortamı | GitHub'ın Windows makinesi (`windows-latest`), Windows PowerShell 5.1 (`shell: powershell`): script'ler bu ortamda denendi |
| Deploy mantığı | Mevcut `deploy/*.ps1` script'leri; ikinci bir deploy yolu yazılmaz |
| AWS kimliği | GitHub OIDC + IAM rolü; kalıcı access key ve GitHub secret yok |
| Altyapı çıktıları | SSM Parameter Store'da gizli olmayan bir JSON parametresi; CI rolünün Terraform state'ine erişimi **yok** (state origin secret'ı içerir) |
| GitHub environment | Kullanılmaz (OIDC `sub` claim'ini değiştirir; tek kişilik repo) |

## Kapsam

### 1. CI iş akışı (`.github/workflows/ci.yml`)

Tetikleyici: `push` (tüm dallar) ve `pull_request`. Makine `ubuntu-latest`. İşler paralel:

- **backend:** `actions/setup-dotnet` (`global-json-file: global.json`), `dotnet test backend/WatchParty.slnx`.
- **frontend:** Node 22, `npm ci`, `npm test`, `npm run build` (`frontend/` içinde).
- **infra:** Terraform `>= 1.10` (`hashicorp/setup-terraform`), `terraform -chdir=infra fmt -check -recursive`, `terraform -chdir=infra init -backend=false`, `terraform -chdir=infra validate`; Node ile `node --test "infra/tests/*.test.mjs"`; `bash deploy/tests/remote-deploy.test.sh`.
- **downloader:** Python 3.12+, `pip install -r tools/downloader/requirements.txt`, `tools/downloader` içinde `python -m unittest`.

İzinler: `contents: read`. Aynı daldaki eski koşu yeni push gelince iptal edilir (`concurrency` + `cancel-in-progress`).

### 2. Deploy iş akışı (`.github/workflows/deploy.yml`)

- Tetikleyici: yalnızca `workflow_dispatch`, girdi `hedef` (`choice`: `frontend`, `backend`, `ikisi`; varsayılan `frontend`).
- `master` dışındaki bir daldan başlatılırsa iş ilk adımda hata verip durur (rol zaten yalnızca `master`'a güvenir; bu, anlaşılır bir hata mesajı içindir).
- `concurrency: deploy` (`cancel-in-progress: false`): aynı anda tek deploy.
- İzinler: `id-token: write`, `contents: read`.
- Makine `windows-latest`. Adımlar:
  1. Checkout; .NET (`global.json`) ve Node 22 kurulumu.
  2. `aws-actions/configure-aws-credentials` ile rolü üstlenme; rol ARN'si repo değişkeni `AWS_DEPLOY_ROLE_ARN`'den, bölge `eu-north-1`.
  3. `hedef` `backend` ya da `ikisi` ise `deploy\deploy-backend.ps1 -Profile ""` (testler script'in içinde koşar).
  4. `hedef` `frontend` ya da `ikisi` ise `deploy\deploy-frontend.ps1 -Profile ""`. Sıra her zaman önce backend.
  5. Canlı smoke: `backend/e2e` içinde `npm ci` ve `npm run smoke`; `BASE_URL=https://<cloudfront_domain>` ve `ORIGIN_URL=http://<origin_domain>`, değerler 3. bölümdeki SSM parametresinden okunur.
- Ortam değişkeni `WP_OUTPUTS_FROM_SSM=1` tüm iş boyunca ayarlıdır.
- Bir adım başarısız olursa iş kırmızı biter. Backend tarafındaki otomatik geri dönüş (sağlık kontrolü 20 sn'de 200 dönmezse önceki sürüm) sunucuda olduğu için CI'da da aynen çalışır.

### 3. AWS tarafı (`infra/github.tf`, Terraform)

- **OIDC sağlayıcısı:** `aws_iam_openid_connect_provider`, URL `https://token.actions.githubusercontent.com`, client id `sts.amazonaws.com`.
- **Rol `watchparty-github-deploy`:** güven politikası yalnızca bu sağlayıcıdan `sts:AssumeRoleWithWebIdentity`, koşullar `aud = sts.amazonaws.com` ve `sub = repo:iamhankaya/watchparty:ref:refs/heads/master` (`StringEquals`). Repo adı değişken olur: `github_repo` (varsayılan `iamhankaya/watchparty`). Oturum süresi varsayılan (1 saat).
- **Rol yetkileri (satır içi politika, en dar hali):**
  - Site bucket'ı: `s3:ListBucket` bucket üzerinde; `s3:PutObject`, `s3:GetObject` nesneler üzerinde. **`s3:DeleteObject` yok** (deploy-frontend hiçbir şey silmez; `videolar/` korunur).
  - Deploy bucket'ı: `s3:PutObject` yalnızca `backend/*` altında.
  - CloudFront: `cloudfront:CreateInvalidation`, `cloudfront:GetInvalidation` yalnızca bu dağıtımın ARN'si üzerinde.
  - SSM komutu: `ssm:SendCommand` bu instance'ın ARN'si ve `arn:aws:ssm:eu-north-1::document/AWS-RunShellScript` üzerinde; `ssm:GetCommandInvocation`, `ssm:ListCommandInvocations` (`*`: kaynak düzeyinde kısıtlanamıyor).
  - Çıktı parametresi: `ssm:GetParameter` yalnızca `/watchparty/infra-outputs` üzerinde.
  - State bucket'ına (`watchparty-tfstate-*`) hiçbir izin verilmez.
- **SSM parametresi `/watchparty/infra-outputs`:** `aws_ssm_parameter`, tip `String`, değeri `jsonencode` ile `cloudfront_domain`, `distribution_id`, `site_bucket`, `deploy_bucket`, `instance_id`, `origin_domain` (outputs.tf ile aynı adlar). Gizli değer içermez. Terraform her apply'da günceller.
- **Çıktı:** `github_deploy_role_arn`.
- `apply` yalnızca yeni IAM/SSM kaynakları ekler; mevcut kaynaklara (CloudFront, EC2, bucket'lar) dokunmaz. Plan bunu doğrulamalıdır: "N to add, 0 to change, 0 to destroy".

### 4. Script değişiklikleri (`deploy/common.ps1`, `deploy-backend.ps1`, `deploy-frontend.ps1`)

- `Invoke-Aws`: `$Profile` boş ise `--profile` eklenmez (aws CLI ortamdaki OIDC kimliğini kullanır). Dolu ise bugünkü gibi.
- `Get-InfraOutputs`: `$env:WP_OUTPUTS_FROM_SSM -eq "1"` ise çıktıları `aws ssm get-parameter --name /watchparty/infra-outputs` ile okur ve parametre değerini JSON olarak çözer; değilse bugünkü `terraform output -json` yolu. Her iki yolda aynı nesne döner ve aynı zorunlu anahtar kontrolü yapılır. Parametre okuma salt okunur olduğu için `-DryRun` altında da gerçekten çalışır (aksi halde DryRun çıktısız kalır).
- Varsayılan `-Profile watchparty` ve lokal davranış değişmez.

### 5. Belgeler ve tek seferlik kurulum

- `deploy/README.md`: "GitHub Actions" bölümü — CI'ın ne kontrol ettiği, deploy'un nasıl başlatıldığı (Actions → Deploy → Run workflow → hedef), ilk kurulum (`terraform apply`, ardından `gh variable set AWS_DEPLOY_ROLE_ARN --body <çıktı>`), rolün yetki sınırları.
- `CLAUDE.md` Deployment bölümüne kısa not; `docs/BACKLOG.md`'den CI/CD maddesi silinir.
- Tek seferlik: `terraform apply` (kullanıcı onayıyla) ve repo değişkeni `AWS_DEPLOY_ROLE_ARN`'nin ayarlanması.

## Doğrulama

- Lokal (apply sonrası): `deploy-frontend.ps1 -DryRun` hem bugünkü haliyle hem `$env:AWS_PROFILE="watchparty"`, `$env:WP_OUTPUTS_FROM_SSM="1"`, `-Profile ""` ile aynı bucket/dağıtım değerlerini içeren `aws` komutlarını yazdırır (ikincisinde `--profile` yok).
- CI iş akışı bir push ile koşar ve tüm işler yeşil biter.
- Deploy iş akışı önce `hedef: frontend` ile denenir (lobileri düşürmez); smoke 6/6.
- `hedef: backend` denemesi, açık bir izleme oturumu yokken, kullanıcıya sorularak yapılır.
- Rolün dar olduğunun kontrolü: rolle state bucket'ını okuma denemesi `AccessDenied` döner (`aws sts assume-role` yerine IAM policy simulator: `aws iam simulate-principal-policy`).

## Kapsam dışı

- Push'ta otomatik deploy, PR önizleme ortamları.
- `terraform apply`'ın CI'dan çalıştırılması (state erişimi gerektirir).
- Lokal deploy kullanıcısının (`watchparty-deploy`, AdministratorAccess) daraltılması: backlog'da ayrı madde olarak kalır.
- Dependabot / bağımlılık güncellemeleri.
