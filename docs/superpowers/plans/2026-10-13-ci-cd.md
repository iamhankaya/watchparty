# CI/CD (GitHub Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Her push/PR'da otomatik kontroller ve GitHub'dan elle başlatılan, mevcut PowerShell script'lerini kullanan deploy.

**Architecture:** `ci.yml` Linux'ta testleri ve build'i koşar, AWS'ye dokunmaz. `deploy.yml` Windows makinesinde OIDC ile dar yetkili bir IAM rolünü üstlenir ve `deploy/*.ps1`'i `-Profile ""` ile çalıştırır; altyapı çıktılarını Terraform state'i yerine SSM parametresi `/watchparty/infra-outputs`'tan okur. Rol, parametre ve OIDC sağlayıcısı `infra/github.tf`'te.

**Tech Stack:** GitHub Actions, Terraform (hashicorp/aws ~> 6.0), Windows PowerShell 5.1 (deploy), PowerShell 7 (CI'da script testi), aws CLI v2 (runner'larda kurulu), Node 22, .NET SDK (`global.json`), Python 3.12.

**Spec:** `docs/superpowers/specs/2026-10-13-ci-cd.md`

## Global Constraints

- Kod yorumları, commit mesajları, script çıktıları ve dokümanlar Türkçe. Commit mesajları `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` ile biter.
- Bölge `eu-north-1`. Repo `iamhankaya/watchparty`, dal `master`.
- Sabit adlar (tüm task'lar bunları birebir kullanır):
  - SSM parametresi: `/watchparty/infra-outputs` (tip `String`, JSON; anahtarlar `cloudfront_domain`, `distribution_id`, `site_bucket`, `deploy_bucket`, `instance_id`, `origin_domain`).
  - Ortam değişkeni: `WP_OUTPUTS_FROM_SSM` (değer `"1"` iken SSM yolu).
  - IAM rolü: `watchparty-github-deploy`; Terraform çıktısı `github_deploy_role_arn`; Terraform değişkeni `github_repo` (varsayılan `"iamhankaya/watchparty"`).
  - GitHub repo değişkeni: `AWS_DEPLOY_ROLE_ARN`.
  - Script testi: `deploy/tests/common.test.ps1`.
  - Deploy girdisi: `hedef`, seçenekler `frontend`, `backend`, `ikisi` (varsayılan `frontend`).
- Lokal davranış değişmez: `-Profile` varsayılanı `watchparty`, `WP_OUTPUTS_FROM_SSM` yokken `terraform output -json`.
- Deploy rolünün Terraform state bucket'ına (`watchparty-tfstate-*`) ve `s3:DeleteObject`'e izni yok.
- Terraform state, `*.tfvars`, `infra/.terraform/` repoya girmez. Worktree'lerde `terraform plan/apply` çalıştırılmaz (tfvars ve state erişimi yalnızca ana çalışma ağacında, controller tarafından).
- `.ps1` dosyaları mevcut dosyalar gibi UTF-8 **BOM'lu** kalır (PowerShell 5.1 Türkçe karakterleri ancak böyle doğru okur).

## Review Focus

- **SSM parametresinde anahtar eksik** (ör. eski bir apply'dan kalma): Terraform yolundaki gibi `infra çıktıları eksik (<anahtar>)` hatası. → Task 2 testi `ssm_eksik_anahtar`.
- **`WP_OUTPUTS_FROM_SSM=1` iken parametre okunamıyor** (yetki/ad hatası): sessizce boş nesne değil, Türkçe anlaşılır hata. → Task 2 testi `ssm_okuma_hatasi`.
- **`-DryRun` + SSM yolu:** parametre okuma gerçekten çalışır, yazan komutlar yalnızca yazdırılır. → Task 2 testi `dryrun_ssm_okur`.
- **Deploy `master` dışından başlatılır:** iş ilk adımda Türkçe mesajla durur, AWS'ye hiç gitmez. → Task 3 ilk adım.
- **Rol güven koşulu gevşek** (`StringLike`, joker, PR ref'leri): yalnızca `StringEquals` ve `repo:iamhankaya/watchparty:ref:refs/heads/master`. → Task 1 Step 2 `grep` kontrolü.

- [ ] **Step 1: `infra/github.tf` yaz.** Spec 3. bölümdeki kaynaklar ve izinler birebir:
  - `aws_iam_openid_connect_provider.github`: url `https://token.actions.githubusercontent.com`, `client_id_list = ["sts.amazonaws.com"]` (thumbprint verilmez; provider 6.x'te isteğe bağlı).

  - `aws_iam_role_policy.github_deploy`: spec'teki izin listesi; SSM instance ARN'si `arn:aws:ec2:${var.region}:${data.aws_caller_identity.current.account_id}:instance/${aws_instance.api.id}` (hesap kimliği için `data "aws_caller_identity"` — `infra/` içinde zaten varsa onu kullan), doküman ARN'si `arn:aws:ssm:${var.region}::document/AWS-RunShellScript`, parametre ARN'si `aws_ssm_parameter.infra_outputs.arn`.
  - `aws_ssm_parameter.infra_outputs`: `name = "/${var.project}/infra-outputs"`, `type = "String"`, `value = jsonencode({...})` altı anahtarla (değerler `outputs.tf`'tekiyle aynı ifadeler).
  - Dosya başına kısa Türkçe açıklama: rol yalnızca `master`'dan, state bucket'ına erişimi yok, parametre gizli değer içermez.
- [ ] **Step 2: Doğrula.**

  `terraform plan` ÇALIŞTIRMA (controller ana ağaçta yapar).

### Task 3: İş akışları

**Files:**
- Create: `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: `WP_OUTPUTS_FROM_SSM`, `/watchparty/infra-outputs`, `AWS_DEPLOY_ROLE_ARN`, `deploy/tests/common.test.ps1`, `deploy\deploy-backend.ps1 -Profile ""`, `deploy\deploy-frontend.ps1 -Profile ""` (Global Constraints'teki adlar).
- Produces: iş akışı adları `CI` ve `Deploy`.

- [ ] **Step 1: `ci.yml` yaz** — spec 1. bölüm birebir: `name: CI`, `on: push` (tüm dallar) + `pull_request`, `permissions: contents: read`, `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`; dört iş `backend`, `frontend`, `infra`, `downloader` (`ubuntu-latest`). `infra` işine ek adım: `pwsh -NoProfile -File deploy/tests/common.test.ps1`. Action sürümleri: `actions/checkout@v4`, `actions/setup-dotnet@v4` (`global-json-file: global.json`), `actions/setup-node@v4` (`node-version: 22`, npm cache `frontend/package-lock.json`), `hashicorp/setup-terraform@v3` (`terraform_version: "~1.10"` veya üstü; `terraform_wrapper: false`), `actions/setup-python@v5` (`python-version: "3.12"`).
- [ ] **Step 2: `deploy.yml` yaz** — spec 2. bölüm birebir: `name: Deploy`, yalnızca `workflow_dispatch` + `hedef` girdisi (`type: choice`), `permissions: { id-token: write, contents: read }`, `concurrency: { group: deploy, cancel-in-progress: false }`, iş `windows-latest`, `env: WP_OUTPUTS_FROM_SSM: "1"`, tüm `run` adımları `shell: powershell`. Adım sırası:
  1. `github.ref != 'refs/heads/master'` ise `Write-Error "Deploy yalnızca master dalından başlatılabilir."; exit 1` (checkout'tan önce).
  2. Checkout, setup-dotnet, setup-node 22.
  3. `aws-actions/configure-aws-credentials@v4`: `role-to-assume: ${{ vars.AWS_DEPLOY_ROLE_ARN }}`, `aws-region: eu-north-1`.
  4. `if: inputs.hedef != 'frontend'` → `.\deploy\deploy-backend.ps1 -Profile ""`.
  5. `if: inputs.hedef != 'backend'` → `.\deploy\deploy-frontend.ps1 -Profile ""`.
  6. Smoke: `aws ssm get-parameter --name /watchparty/infra-outputs --query Parameter.Value --output text` → JSON'dan `BASE_URL=https://<cloudfront_domain>`, `ORIGIN_URL=http://<origin_domain>`; `backend/e2e` içinde `npm ci` ve `npm run smoke`; `$LASTEXITCODE` sıfır değilse `exit 1`.
- [ ] **Step 3: Doğrula.**
  Run: `python -c "import sys,yaml; [yaml.safe_load(open(p,encoding='utf-8')) for p in sys.argv[1:]]; print('ok')" .github/workflows/ci.yml .github/workflows/deploy.yml` (PyYAML yoksa `pip install pyyaml` geçici bir venv'de ya da `npx --yes yaml-lint` yerine `node -e` ile `yaml` paketi; hangisi kullanıldıysa rapora yaz) → `ok`.
  Run: `grep -n "\${{ *inputs\.\|\${{ *vars\." .github/workflows/deploy.yml` → `run:` gövdelerinde `${{ }}` ifadesi yok (girdiler `if:` ya da `env:` üzerinden geçer; komut enjeksiyonu önlenir).
  Gerçek doğrulama push sonrası controller'da (bu task'ta push yok).
